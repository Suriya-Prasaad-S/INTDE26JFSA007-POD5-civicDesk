## 5. API contract (summary — see API-Reference.md for full detail)

11 endpoints under `/civicDesk/citizenProfile`:
`POST /registerCitizen`, `GET /getProfile/{id}`, `PUT /updateProfile/{id}`, `PUT /updateStatus/{id}`,
`GET /getCitizensByWard/{ward}`, `GET /getAllCitizens`, `POST /{id}/uploadDocument` (multipart),
`GET /{id}/getAllDocuments`, `GET /{id}/getDocumentById/{docId}`,
`PUT /{id}/verifyDocument/{docId}`, `GET /files/{name}`.

**Conventions:**
- **IDs:** `citizenId` / `documentId` are **16-char alphanumeric** (generated by `support/IdGenerator`).
- **Status:** **single-character codes** — citizen `A`/`V`/`F` (Active/Verified/Flagged), document
  `V`/`E`/`R` (Valid/Expired/Revoked). Stored & exposed as the code (via `entity/converter/*`).
- **Responses:** GET → DTO/array (200); POST/PUT → `{ "message": … }` (uploads add `documentId`);
  create → 201. **Register returns the message only — no id** (fetch the id via `getCitizensByWard`/
  `getAllCitizens`).
- **Errors:** body is **`{ "message": … }` only**. Codes: 400 (validation/bad code/bad file),
  403 (verifier not a supervisor), 404 (not found), 409 (duplicate / illegal transition / doc limit),
  413 (upload too large).
- **National ID** is returned **masked** (`****` + last 4).
- **Files** are stored on disk (`citizen.document.storage-dir`, default `./uploads`) and served by
  `GET /files/{name}`; a document's `filePath` is that URL.

**Status transitions:** citizen `A→V`, `A↔F`, `V→F` (not `V→A`). Document `V→V`/`V→R`, `E→R`
(`V→E` is automatic past expiry; `R` is terminal).

**Document rules:** max 5 per citizen, max 2 MB, types PDF/JPG/JPEG/PNG (extension + MIME).

**Verification gate:** `verifyDocument`'s `verifiedBy` must be an **Active `DEPT_SUPERVISOR`** in the
`users` table (looked up via `JdbcTemplate`), else **403**. This is a stand-in for the Tier-3 JWT
role check.

## 6. Key decisions & deviations (read before changing anything)

- **16-char alphanumeric IDs** replace the **project-wide CHAR(36) UUID v4** convention. ⚠️ This
  changes the FK target (`citizen_id` varchar(16)) that Modules 2.3 (Service Requests) and 2.5
  (Grievance) plan to reference — coordinate at integration.
- **snake_case** tables/columns (`citizen_profile`, `citizen_document`, `citizen_id`, …) via explicit
  `@Table`/`@Column` names — the **shared naming strategy was NOT changed**.
- **Single-char status** everywhere (DB + API), per the module owner's request.
- **Security starter commented out** in the **shared `pom.xml`** (temporary, for local Postman
  testing — no SecurityConfig exists yet). **Restore before integrating.**
- **No JUnit** for this module (owner's decision) — verification is the Postman collection + the docs.
  The earlier service unit tests were **deleted** (they referenced removed APIs).
- **Issue-dummy-document removed** entirely (it belonged to Module 2.3).
- **Real file storage** added (`support/FileStorageService`) — earlier it stored only a synthetic path.

## 8. Environment quirks (Windows + corporate network)

- **Maven Central is blocked** by an SSL-intercepting proxy. Any command that downloads (incl.
  `spring-boot:run` the first time) needs the wagon flags shown in §3.
- **Run Maven from PowerShell**, not the Bash tool (Cygwin mangles `/etc`). Run from the **project
  dir**, not the parent.
- **Windows MySQL lowercases table names** — `citizen_profile` shows as `citizen_profile` (already
  lowercase here, so no surprise), and unqualified queries hit your default schema. Query
  `civicdesk.<table>` or set `civicdesk` as the active schema.
- The `mysql` CLI is at `C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe` (not on PATH);
  MySQL Workbench is installed.
